## What was done (all in commit 596e0a7)

### 1. Missing-observation mechanism in the joint filter (`python/argus/jax_kalman_filter.py`)
- `_update(xp, Pp, H, R, z, mask=None)` now accepts a per-epoch `(Npsr,)` mask (1 = observed,
  0 = absent). Absent pulsars: `H_eff = mask[:,None]*H` (zero rows), `R_eff = (m⊗m)*R +
  diag(1−m)` (identity on absent slots → keeps `S` invertible/decoupled), innovation zeroed.
- Threaded through `_run_kalman_filter_scan` (new `mask_matrices` arg, packed into the
  `lax.scan`) and `JaxKalmanFilter` (reads `data["processed_residuals"]["mask"]`, defaults to
  all-ones → backward-compatible).
- **Why it is exact:** each `H` row touches only its own pulsar's states; all cross-pulsar
  coupling is in `Pp`. Masking a pulsar's measurement = the Kalman update conditioned on the
  present pulsars only; the absent pulsar's latent state is still propagated by `_predict`.
- **Golden-preserving:** all-ones mask reproduces the MDC2 likelihood bit-for-bit (63618.93,
  `test/test_likelihood_value.py`).
- Tests (`test/test_jax_kalman_filter.py::TestMaskedUpdate`, `TestMaskedFilterEquivalence`):
  all-ones == no-mask; all-absent update is a no-op; masking pulsar 1 == reduced-dimension
  update; appending all-absent epochs shifts LL by exactly the log(2π) constant; a masked
  pulsar's data cannot change the likelihood.
- NB: a masked-absent slot adds a fixed `0.5·log(2π)` per epoch to the *absolute* logL (from the
  identity slot in `S`). It is **θ-independent** → irrelevant for the posterior (amplitude). If a
  future task needs absolute evidence, set the absent diagonal to `1/(2π)` to zero it.

### 2. Union grid + mask in the data layer
- `build_aligned_feathers.py --grid union` (default stays `intersection`): bins onto the
  **union** epoch grid (all cells occupied by *any* pulsar), uses grid-cell reference times,
  fills absent cells with residual 0 / zero design row / placeholder error, and emits a `mask`
  column. `compute_union_grid`, `bin_pulsar_union` are the new functions.
- Mask flows through `save_feather`/`read_feather` (optional `mask` column) →
  `process_pulsar_residuals_by_epoch` (collects `result["mask"]` when every pulsar has one) →
  filter. `data_loader.py` changes are all optional/backward-compatible.
- Data-layer tests in `test/test_data_loader.py::TestFeatherCache` (mask round-trip, epoch
  alignment collects/omits mask).

### 3. HD self-correlation bug fix (`python/argus/gravitational_waves.py`)
- `pairwise_angular_separation` now pins the diagonal to exactly 0 (`np.fill_diagonal(sep,0)`).
  Float noise in `sin²+cos²` left 15/68 pulsars with a self-separation ~1e-5 rad, which slipped
  past `hellings_downs`'s `np.isclose(θ,0)` zero-test → HD **diagonal 0.5 instead of 1.0** →
  halved GW auto-power for those pulsars. Only surfaced at the full array. Golden-safe (diagonal
  was already 0 where it mattered before).

## Key findings

- **`max_tree_depth` must be capped.** The 1266-D posterior has an `h_a↔γ_a` ridge; with
  `max_tree_depth=10` a chain that hit the ridge built ~1000-step trajectories (~400 s/iter) and
  could not finish in walltime, stalling the whole parallel run (job **14178734** died at
  walltime, no output). **Capped 10→7** → each iter ≤127 leapfrog steps (~50–80 s/iter steady),
  all chains guaranteed to finish. This is baked into all three full configs.
- **Probe timing (job 14173193, 1×A100):** 0.26 s / likelihood eval (compiled). Extrapolated:
  1000+2000 iters ≈ **~2.5–3 days** on 4×A100 at depth 7.
- **Quick-look (job 14195666, 4×A100, 300+500, depth 7, 17.7 h, COMPLETED):**
  - `log10_ha`: per-chain means [−13.42, **−12.65**, −13.39, −13.41]; median **−13.40**.
  - Band-referenced amplitude **OVERLAPS published NG15** at f=1/(5yr) (−0.74σ vs fixed γ=13/3),
    matching the 6-psr subset (−13.40 ± 0.20). `log10_ha` off the prior edges. 3.05% divergences.
  - **NOT converged:** r_hat ≈ 9.8 (log10_ha), 13.2 (log10_gamma_a), up to ~16 on per-pulsar
    `log10_σp[63..67]` (short-baseline pulsars); min ESS ≈ 4. Outputs in
    `outputs/ng15_full_quicklook/` (`comparison.json`, `spectral_overlay.png`,
    `numpyro_diagnostics/`, `*_results.nc`).
  - **Interpretation:** the full-array machinery is validated and the amplitude is sensible and
    consistent — but one chain sits in a different global mode along the ridge, inflating r_hat
    across many params. This is a *sampling-geometry* problem, not a data/likelihood problem.

## Root-cause analysis (accurate — read before "fixing" anything)

The model **already** reparameterizes for NUTS (see `python/argus/parameter_sampling.py`):
- All bounded priors are sampled as `*_prime`/`*_raw ~ Normal(0,1)` then affine-mapped
  (U→N(0,1)). `log10_ha` (line 74), `log10_gamma_a` (line 91) are sampled this way,
  **independently**.
- The hierarchical red noise is **already non-centered**: `log10_γp_raw ~ Normal(0,1)` then
  `log10_γp = mean + raw·std/√n_pulsars` (line 149–154). So the r_hat~15 on `log10_σp` is **not**
  a naive missing-non-centering funnel.

So the convergence failure is **not** fixed by "add non-centering" (it's there). The real
suspects, in priority order:

1. **The `h_a↔γ_a` ridge (leading suspect).** `log10_ha` and `log10_gamma_a` are sampled on
   *independent* axes, but the posterior is a strong, curved correlation between them (the OU
   band-amplitude is the constrained combination; the shape is not — this is the T2.4/T3.3
   pathology). NUTS mixes poorly across a curved ridge that is not aligned with its sampling
   basis, and different chains settle at different points along it → the one-outlier-chain
   behaviour and global r_hat inflation.
2. **The `/√n_pulsars` shrinkage** in `log10_γp` (parameter_sampling.py:154) is unusual and was
   only ever exercised at n=6; at n=68 it forces per-pulsar γp very tightly toward the population
   mean, which may fight the data for the (few) well-constrained pulsars and distort geometry.
   Worth scrutinising / testing with/without.
3. **Short warmup (300).** Too short to adapt the diagonal mass matrix at 1266-D. The production
   config already uses 1000; still, warmup alone will not straighten a curved ridge.

## Recommended next work — option (2b)

**Goal:** get r_hat ≈ 1 on `log10_ha` (and ideally the array) *before* spending ~3 days of
4×A100, by fixing geometry rather than throwing compute at it.

1. **Diagnose first (cheap, use the existing quick-look `.nc`).** Confirm the story with
   `outputs/ng15_full_quicklook/ng15_full_quicklook_results.nc`:
   - Trace/pair-plot `log10_ha` vs `log10_gamma_a` per chain → confirm the ridge and that chain 1
     sits at a distinct point.
   - Check whether the high-r_hat `log10_σp` params are simply following the outlier chain's
     global mode (→ it's really *one* problem: the ridge), vs independently pathological.
2. **Decorrelate the GW corner (the main change).** Options, simplest first:
   - Sample in a **rotated `(log10_ha, log10_gamma_a)` basis** aligned with the ridge — e.g.
     estimate the ridge direction from the quick-look posterior covariance and sample two
     ~orthogonal linear combinations (band-amplitude-like + shape-like) as the `*_prime` sites,
     mapping back to `log10_ha`/`log10_gamma_a` deterministically. Edit `sample_gw_parameters`
     in `parameter_sampling.py` (keep the deterministic `log10_ha`/`log10_gamma_a`/`γa` site
     names so downstream + comparison scripts are unchanged).
   - OR try `dense_mass=true` **restricted to the GW block** (numpyro supports per-block dense
     mass via `dense_mass=[("log10_ha_prime","log10_gamma_a_prime")]`) — cheaper to try than a
     hand-rolled rotation and directly learns the 2×2 correlation. **Try this first** — it may be
     enough and needs only a config/one-line model change.
   - Reconsider the `/√n_pulsars` factor while in there.
3. **Verify the reparameterization is posterior-preserving.** It must change only geometry: check
   the joint log-density at a fixed point matches pre-change (same trick as the T3.4 LHM Route-B
   check), and the MDC2 golden likelihood is untouched. Add/extend a test.
4. **Cheap convergence check**, then the production run. Re-run the quick-look settings (or a
   500+500) with the new geometry; if r_hat drops toward ~1, launch `ng15_full_run.sh`
   (1000+2000, depth 7, 4 chains, ~2.5–3 days). Validate with
   `scripts/compare_ou_recovery.py --published --run-prefix ng15_full
   --data-path <repo>/workflows/ng15_sgwb_demo/data/aligned_full`.

**Alternative / complementary lever — long-baseline subset.** The worst-mixing pulsars are the
short-baseline ones (present in <40% of epochs, poorly constrained noise). Restricting to the
~30–40 pulsars with ≥8 yr baseline would (a) shrink `nx`, (b) ease the geometry, and (c) run in
~1 day, while carrying essentially all the low-frequency SGWB signal. If a converged full-68
result proves stubborn, this is the pragmatic fallback and arguably better science-per-GPU-hour.
Stage it with an explicit `--subset` list to `stage_symlinks.py` (or add a baseline filter).
